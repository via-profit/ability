# Changelog

## [3.8.2] - 2026-10-27

### ⚠️ Изменения поведения
- Группа `all of:` / `any of:` с отступом больше, чем у заголовка внешней группы, теперь вложенная (раньше отступы не учитывались, и она становилась отдельной группой политики). Политики, где группы записаны «лесенкой», начнут вычисляться так, как написаны, — проверьте их.
- `except` внутри группы (с отступом больше, чем у заголовка группы) — ошибка разбора; раньше он молча становился блоком `except` всей политики.

### Added
- Вложенные группы: в DSL (по отступу, любая глубина, в том числе внутри `except`), в API (`AbilityRuleSet.ruleSets`, `addRuleSet()`, `addRuleSets()`, `extractRules()`, `snapshot()`), в JSON (поле `ruleSets` группы, только у групп с вложенными группами), в explain и в генераторе типов. Документация — раздел «Вложенные группы».

### Fixed
- Вложенная группа `any of:` внутри `all of:` (и наоборот) вычислялась неверно: парсер выносил её на уровень политики, а внешняя группа проверялась без неё. Для политики `if any:` это выдавало доступ без условия вложенной группы (например, программист мог менять чужую задачу).

## [3.8.1] - 2026-09-25

### ⚠️ Изменения поведения
- Строка в кавычках справа в правиле теперь всегда литерал (`domain.version equals '1.2.3'`), путь — только идентификатор без кавычек. В JSON правил добавлено поле `resourceType` (`value` | `path`); JSON без него читается по прежнему правилу.
- Левая часть правила всегда путь, в том числе без точки (`role equals 'admin'` читает поле `role` ресурса).
- Пути `env.*` ищутся только в environment; поле `env` внутри ресурса больше не используется.
- `onDeny`/`onAllow` из опций резолвера вызываются только в `enforce()`; `resolve()` коллбэки не вызывает.
- Wildcard `*` в середине ключа совпадает ровно с одним сегментом (`*.create` больше не совпадает с `order.update`).
- Фильтр по тегам всегда учитывает политики без тегов (как и было описано в документации).
- Группа без активных правил не участвует в проверке; политика без активных групп не совпадает (раньше такая политика совпадала).
- Автоматические ID политик и групп вычисляются из полного содержимого, включая правила (раньше у разных политик с одинаковым заголовком ID совпадали).
- Парсер стал строже, см. раздел «Проверки при разборе DSL» в документации.

### Added
- Сайт документации с песочницей (`website/`): документация из `docs/` на русском и английском, поиск, живая проверка политик с explain и генерацией типов.
- Страница документации «Введение» (`docs/*/getting-started.md`).
- Операторы `is empty`, `is not empty`, `starts with`, `ends with`, `contains all`, `contains any`.
- Дробные и отрицательные числа в DSL (`-1`, `0.5`), `null` в массивах.
- Проверки при разборе DSL: неизвестные и повторяющиеся аннотации (с подсказкой для опечаток), аннотации без значения, некорректные `@priority`/`@disabled`/`@tags`, «висящие» аннотации, повторяющиеся `@id`, пустые политики и группы, политика только из `except`, неизвестные и повторные алиасы, алиасы с несколькими правилами, несоответствие значения оператору.
- Экспорт `AbilityDSLSyntaxError` из пакета; ошибки лексера теперь тоже `AbilityDSLSyntaxError` с позицией и фрагментом DSL.
- Статусы `EXCEPT ✗` и `SKIPPED …` в explain.
- В генераторе типов поля wildcard-политик добавляются в подходящие конкретные ключи.
- `description` сохраняется при JSON-сериализации политик, групп и правил.
- Кеш политик по ключу разрешения в `AbilityResolver` (до 1024 ключей): проверка ускорилась в 2–10 раз и почти не зависит от общего числа политик.
- Условие `types` в `exports` и отдельные типы `index.d.cts` для CommonJS.

### Fixed
- Отключённая после проверки политика (`policy.disabled = true`) продолжала участвовать в решении со статусом прошлой проверки.
- JSON-сериализация теряла признак `except` у групп — на клиенте исключение превращалось в обычное условие.
- `@priority 0` превращался в `-1`.
- Explain у ранее полученного `AbilityResult` менялся после следующих вызовов `resolve()`; правила, до которых не дошла проверка, показывали статус из прошлой проверки.
- Политика, отменённая блоком `except`, отображалась в explain как `DISABLED`.
- `EnforceOptions.onAllow` никогда не вызывался.
- Оператор `less` без `than` не разбирался; `always`/`never` нельзя было использовать в явных группах и `except`.
- `copyWith` терял `disabled`, `isExcept`, `tags`.
- Состояние алиаса разделялось между политиками, которые его используют.
- Документация: примеры, которые не разбирались, опечатки (`@diasbled`, `equeals`), описание `is null`/`is not null` (проверка строгая, `undefined` — не `null`), количество стратегий (8), теги в `resolve`/`enforce`, типы `date` у операторов сравнения, JSDoc `PriorityStrategy`.

### Removed
- Неиспользуемые devDependencies: `@jagi/jest-transform-graphql`, `jest-transform-graphql`, `@jest/types`, `concurrently`, `nodemon`, `rollup-plugin-copy`, `ts-loader`, `ts-node`, `typescript-eslint`. Добавлен явный `tslib` (peer-зависимость `@rollup/plugin-typescript`).

## [3.7.7] - 2026-09-07

### Added
- Добавлены методы `explainToString()` и `explainToJSON()` для детального представления результата проверки разрешений.
- Добавлена JSON-сериализация объяснений политик и правил.
- Добавлена английская документация по DSL, резолверу, стратегиям, генерации типов и работе на сервере и в браузере.
- Расширено тестовое покрытие методов объяснения результата.

### Changed
- Метод `explain()` теперь возвращает строковое представление результата.
- README переведён на английский язык и обновлены примеры использования.

### Fixed
- Исправлена ошибка форматирования блока кода в русской документации.
- Удалены отладочные сообщения из тестов.
