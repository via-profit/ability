# Ability DSL

Ability DSL — это декларативный язык для описания политик доступа.  
Он позволяет описывать правила в человекочитаемом виде, а затем использовать их в рантайме для принятия решений.

## Базовая структура

```
# <comment-line>
@<annotation>
<effect> <permission> if <all|any>:
    <all|any> of: <subject> <operator> <value|resource|env>
    <all|any> of: <subject> <operator> <value|resource|env>
    ...
    except <all|any> of:
      <subject> <operator> <value|resource|env>
      <subject> <operator> <value|resource|env>
      ...
```

где:

- `comment-line` - комментарий
- `annotation` - аннотация (`@id`, `@name`, `@description`, `@disabled`, `@tags`, `@priority`)
- `effect` – `permit` или `deny`
- `permission` – ключ разрешения с префиксом `permission.` (например, `permission.order.update`)
- `all` / `any` – логический оператор для группы правил
- `except` - начало блока исключений

## Политика

Политика состоит из конструкции:

```
@<annotation>
<effect> <permission> if <all|any>:
  <group>
  <group>
```

где:

- **annotation** - аннотация (`@id`, `@name`, `@disabled`, `@description`, `@tags`, `@priority`);
- **effect** — `permit` | `allow` или `deny` | `forbidden`
- **permission** — ключ разрешения (permission key) - строка вида `permission.foo.bar`  
  (префикс `permission.` обязателен в DSL, но автоматически удаляется парсером)
- **if all:** — все группы должны быть истинны
- **if any:** — хотя бы одна группа должна быть истинна
- политика может содержать одну или несколько групп правил

**Пример**

```dsl
permit permission.order.update if any:
  all of:
    user.roles contains 'admin'
    user.token is not null

  any of:
    user.roles contains 'developer'
    user.login is equals 'dev'
```

### Ключ разрешения (permission key)

Ключи разрешений записываются в формате `dot notation` и поддерживают wildcard‑шаблоны с помощью символа `*`.  
Это позволяет группировать разрешения и переопределять поведение для целых семейств операций.

**Пример использования wildcard-шаблонов**

| Политика (permission) | ключ                   | Совпадает |
|-----------------------|------------------------|-----------|
| `order.*`             | `order.create`         | да        |
| `order.*`             | `order.update`         | да        |
| `order.*`             | `order.item.update`    | да        |
| `order.*`             | `user.create`          | нет       |
| `*.create`            | `order.create`         | да        |
| `*.create`            | `user.create`          | да        |
| `*.create`            | `order.update`         | нет       |
| `*.create`            | `order.item.create`    | нет       |
| `user.profile.*`      | `user.profile.update`  | да        |
| `user.profile.*`      | `user.settings.update` | нет       |
| `*`                   | любой ключ             | да        |

- `*` в конце ключа совпадает со всеми оставшимися сегментами (`order.*` → `order.item.update`).
- `*` в середине ключа совпадает ровно с одним сегментом (`*.create` → `order.create`, но не `order.item.create`).


### Аннотации политик

Аннотации указываются **непосредственно перед определением политики** (каждая на отдельной строке). Формат:
`@имя_аннотации значение`.

#### Поддерживаемые аннотации

| Аннотация      | Тип значения               | Обязательная | Значение по умолчанию      | Описание                                                             |
|----------------|----------------------------|--------------|----------------------------|----------------------------------------------------------------------|
| `@id`          | строка                     | нет          | автоматически генерируется | Уникальный идентификатор политики.                                   |
| `@name`        | строка                     | нет          | формируется из правила     | Человекочитаемое название политики.                                  |
| `@description` | строка                     | нет          | –                          | Подробное описание того, что разрешает/запрещает политика.           |
| `@tags`        | список строк через запятую | нет          | `[]`                       | Теги для фильтрации политик в `AbilityResolver`.                     |
| `@disabled`    | `true` или `false`         | нет          | `false`                    | Если `true`, политика игнорируется при проверке.                     |
| `@priority`    | целое число                | нет          | `-1`                       | Чем выше число, тем раньше политика применяется (при прочих равных). |

#### Примеры использования

```dsl
# Простая политика с ID и названием
@id order_delete_001
@name "Удалять заявку может только администратор"
permit permission.order.delete if all:
  user.roles contains 'admin'

# Отключённая политика с тегами
@disabled true
@tags security, audit, v2
deny permission.user.block if any:
  user.status in ['blocked', 'deleted']

# Политика с приоритетом и описанием
@priority 10
@description "Разрешает редактирование черновиков самому автору и модераторам"
permit permission.post.update if all:
  user.id equals post.author_id
  any of:
    user.roles contains 'moderator'
```

#### Примечания

- Если `@name` не указан, в качестве имени используется ID. Если не указан `@id`, он генерируется из содержимого
  политики (эффект, ключ, группы и правила), поэтому у одинаковых политик одинаковый ID, а у разных — разный.
- Значения строковых аннотаций (`@name`, `@description`, `@id`) **не нужно** заключать в кавычки, если они не содержат
  пробелов. При наличии пробелов используйте двойные кавычки.
- В `@tags` теги разделяются запятыми, пробелы после запятых игнорируются. Сам тег не может содержать пробелы и
  квадратные скобки: пишите `@tags admin, user`, а не `@tags ["admin", "user"]`.
- `@priority` — целое число, в том числе `0` и отрицательные значения.
- `@disabled` без значения равнозначен `@disabled true`.
- Приоритет влияет на порядок оценки политик в стратегии (например, `FirstMatchStrategy` или
  `PriorityStrategy`). По умолчанию все политики имеют приоритет `-1` и оцениваются в порядке объявления.
- Неизвестные аннотации, повторы одной аннотации и аннотации без значения приводят к ошибке разбора.
  Подробнее — в разделе [Проверки при разборе DSL](#проверки-при-разборе-dsl).

## Группа правил

Группа определяет, как объединяются правила внутри неё:

```
all of:
  <rule>
  <rule>

any of:
  <rule>
  <rule>
```

- `all of:` — логическое AND
- `any of:` — логическое OR

`all of` - значит, что группа считается выполненной, если все правила внутри группы сработали.

`any of` - значит, что группа считается выполненной, если хотя бы одно правило внутри группы сработало.

Каждая группа внутри политики будет вычисляться независимо от других групп. Итоговая оценка результата будет определена
путем сравнения результата вычисления всех групп в политике.

### Аннотации групп

Аннотации указываются **непосредственно перед определением группы** (каждая на отдельной строке). Формат:
`@имя_аннотации значение`.

#### Поддерживаемые аннотации

| Аннотация      | Тип значения       | Обязательная | Значение по умолчанию      | Описание                                       |
|----------------|--------------------|--------------|----------------------------|------------------------------------------------|
| `@id`          | строка             | нет          | автоматически генерируется | Уникальный идентификатор группы.               |
| `@name`        | строка             | нет          | формируется из правила     | Человекочитаемое название группы.              |
| `@description` | строка             | нет          | –                          | Подробное описание того, что проверяет группа. |
| `@disabled`    | `true` или `false` | нет          | `false`                    | Если `true`, группа игнорируется при проверке. |

### Неявная группа (implicit group)

Если правила описаны без `all of:` или `any of:`, они объединяются оператором политики:

```dsl
permit permission.order.update if all:
  user.roles contains 'admin'
  user.token is not null
```

Эквивалентно:

```dsl
permit permission.order.update if all:
  all of:
    user.roles contains 'admin'
    user.token is not null
```

_Замечание: Неявная группа всегда соответствует оператору политики (`if all` или `if any`)._

> **Замечание:** рекомендуется избегать одновременного использования неявных (implicit) и явных (explicit) групп в одной политике.
>
> Неявные группы предназначены для кратких и простых политик, где структура очевидна без дополнительных ключевых слов. Явные группы (`all of:`, `any of:`) используются для более сложной логики и всегда имеют приоритет в структуре разбора.
>
> Смешивание этих двух подходов может приводить к неоднозначному восприятию структуры политики. В частности, может возникнуть ситуация, когда явная группа поглощает все последующие неявные группы, интерпретируя их правила как часть собственной области.


### Исключающая группа (except)

Блок `except` определяет условия, которые отменяют действие политики, даже если основная группа правил выполнена.

- Если основная группа истинна и блок `except` выполнен → политика не применяется (как будто она не совпала). Эффект
  **не** инвертируется: `deny`-политика не превращается в `permit`, она просто не участвует в решении.
- Если основная группа ложна → `except` не проверяется.
- Политика не может состоять только из блока `except` — в ней должно быть хотя бы одно правило вне `except`.

> [!NOTE] Исключающая группа — это механизм отмены политики после того, как её основная группа уже дала “истину”. Т.е. политика как будто бы должна сработать, но except говорит: «нет, в этих условиях она не действует». Наиболее частое применение - запрещающие политики (deny). 

```dsl
@name "Редактировать заказ может только авторизованный пользователь"
permit permission.order.update if all:
  user.token is not null

@name "Запрещено обновлять заказ, если он уже выполнен, кроме админов"
deny permission.order.update if all:
  all of:
    order.status equals 'completed'
  except any of:
    user.role is equals 'administrator'
```

**Логика работы**

**1. Проверка авторизации**
- Если `user.token is not null` → **permit** на обновление заказа.
- Если токена нет → основная группа ложна → политика не применяется → разрешение не выдается → итог **deny**, если нет других разрешающих политик.

**2. Проверка статуса заказа**
- Если `order.status equals 'completed'` → основная группа истинна → политика готова выдать **deny**.

**2.1. Проверка исключений (except)**
- Если `user.role equals 'administrator'` → условие `except` истинно → **deny отменяется** → итог **permit** (его
  даёт первая политика).
- Если роль не администратор → `except` ложен → **deny применяется** → обновление выполненного заказа запрещено.


## Правило

Правило — это атомарное условие внутри политики. Оно определяет, при каких данных политика будет считаться совпавшей. С
помощью правил задаются условия по которым определяется эффект политики (`permit` или `deny`)

*Структура правил*:

```
<subject> <operator> <value|resource|env>
```

где:

- **subject** — путь (dot-notation) к проверяемому полю ресурса или окружения (`user.age`, `env.ip`). Левая часть
  правила **всегда** путь, даже без точки: `role equals 'admin'` сравнивает поле `role` ресурса.
- **operator** — оператор сравнения.
- **value** — значение или путь:
    - **литерал** — строка в кавычках (`'admin'`, `"1.2.3"`), число, `true`/`false`, `null` или массив;
    - **путь** — идентификатор **без кавычек** с точкой (`user.id`, `env.request.ip`).

Строка в кавычках — всегда литерал, даже если в ней есть точки: `domain.version is equals '1.2.3'` сравнивает версию
со строкой `1.2.3`. Идентификатор без кавычек и без точки справа — ошибка разбора (скорее всего, забыты кавычки).

_Значение указывается не для всех операторов (например оператор `is null` не требует значения)_

**Пример правил**

```
# Простое правило
user.role equals "admin"

# Сравнение с числом
user.age >= 18

# Проверка вхождения в массив
user.status in ["active", "verified"]

# Сравнение с другим полем ресурса (путь без кавычек)
document.author equals user.id

# Строка с точками — литерал, потому что в кавычках
domain.version equals '1.2.3'
```

### Оператор

**Базовые операторы сравнения**

| Оператор DSL              | Синонимы                 | Пример                              | Описание            | Типы                    |
|---------------------------|--------------------------|-------------------------------------|---------------------|-------------------------|
| **is equals**             | `=`, `==`, `is` `equals` | `user.age is equals 18`             | Строгое равенство   | number, string, boolean |
| **is not equals**         | `!=`, `<>`, `not equals` | `user.role is not equals 'admin'`   | Строгое неравенство | number, string, boolean |
| **greater than**          | `>`, `gt`, `greater`     | `user.age greater than 18`          | Больше              | number                  |
| **greater than or equal** | `>=`, `gte`              | `user.age greater than or equal 18` | Больше или равно    | number                  |
| **less than**             | `<`, `lt`, `less`        | `user.age less than 18`             | Меньше              | number                  |
| **less than or equal**    | `<=`, `lte`              | `user.age less than or equal 18`    | Меньше или равно    | number                  |

Числа могут быть дробными и отрицательными: `account.balance >= -100`, `order.discount < 0.25`.

Сравнение строгое (`===`), без приведения типов: `user.age equals '18'` не совпадёт с числом `18`.
Операторы сравнения работают только с числами. Если одно из значений не число — правило не совпадает.

**Null‑операторы**

| Оператор DSL    | Синонимы            | Пример                        | Описание                        | Типы |
|-----------------|---------------------|-------------------------------|---------------------------------|------|
| **is null**     | `== null`, `= null` | `user.middleName is null`     | Значение строго равно `null`    | any  |
| **is not null** | `!= null`           | `user.middleName is not null` | Значение строго не равно `null` | any  |

> [!IMPORTANT]
> Проверка на `null` строгая: `undefined` — это **не** `null`. Если поля нет в ресурсе, то `is null` не совпадёт, а
> `is not null` — **совпадёт**. Чтобы проверить, что значение действительно задано, используйте вместе
> `is defined` и `is not null`:
>
> ```dsl
> permit permission.order.update if all:
>   user.token is defined
>   user.token is not null
> ```

**Defined‑операторы**

| Оператор DSL       | Синонимы | Пример                           | Описание                             | Типы |
|--------------------|----------|----------------------------------|--------------------------------------|------|
| **is defined**     | -        | `user.middleName is defined`     | Значение определено (не `undefined`, при этом может быть `null`) | any  |
| **is not defined** | -        | `user.middleName is not defined` | Значение не определено (`undefined`) | any  |

**Операторы для списков (массивов)**

| Оператор DSL     | Синонимы                  | Пример                                         | Описание                                  | Типы           |
|------------------|---------------------------|------------------------------------------------|-------------------------------------------|----------------|
| **in [...]**     | `is in`                   | `user.role in ['admin', 'manager']`            | Значение входит в список                  | number, string |
| **not in [...]** | -                         | `user.role not in ['banned']`                  | Значение не входит                        | number, string |
| **contains**     | `includes`, `has`         | `user.tags contains 'vip'`                     | Массив содержит элемент                   | array          |
| **not contains** | `not includes`, `not has` | `user.tags not contains 'vip'`                 | Массив не содержит элемент                | array          |
| **contains all** | -                         | `user.roles contains all ['editor', 'writer']` | Массив содержит **все** элементы списка   | array          |
| **contains any** | -                         | `user.roles contains any ['admin', 'owner']`   | Массив содержит **хотя бы один** элемент  | array          |

- Если в `contains` передать массив, он работает как `contains any`. Для наглядности лучше писать явно `contains any`.
- `contains all` и `contains any` с пустым массивом `[]` — ошибка разбора. Если справа путь и массив по нему пустой,
  правило не совпадает.
- Если левая часть не массив, операторы списков не совпадают.

**Булевые операторы**

| Оператор DSL | Синонимы  | Пример              | Описание         | Типы    |
|--------------|-----------|---------------------|------------------|---------|
| **is true**  | `= true`  | `user.isActive is true`  | Значение истинно | boolean |
| **is false** | `= false` | `user.isActive is false` | Значение ложно   | boolean |

**Примечание:** операторы `is true` и `is false` являются синтаксическим сахаром для `equals true` / `equals false`.

**Операторы длины**

| Оператор DSL            | Синонимы                  | Пример                            | Описание     | Типы          |
|-------------------------|---------------------------|-----------------------------------|--------------|---------------|
| **length equals**       | `length =`, `len =`       | `user.tags length equals 3`       | Длина равна  | array, string |
| **length greater than** | `length >`, `len >`       | `user.tags length greater than 2` | Длина больше | array, string |
| **length less than**    | `length <`, `len <`       | `user.tags length less than 5`    | Длина меньше | array, string |

**Операторы пустоты**

| Оператор DSL     | Синонимы | Пример                    | Описание                                      | Типы          |
|------------------|----------|---------------------------|-----------------------------------------------|---------------|
| **is empty**     | -        | `user.tags is empty`      | Пустая строка `''` или пустой массив `[]`     | array, string |
| **is not empty** | -        | `user.tags is not empty`  | Непустая строка или непустой массив           | array, string |

Для `null`, `undefined` и других типов оба оператора **не** совпадают.

**Строковые операторы**

| Оператор DSL    | Синонимы | Пример                                  | Описание                  | Типы   |
|-----------------|----------|-----------------------------------------|---------------------------|--------|
| **starts with** | -        | `file.path starts with '/public/'`      | Строка начинается с       | string |
| **ends with**   | -        | `user.email ends with '@example.com'`   | Строка заканчивается на   | string |

Сравнение с учётом регистра. Если одно из значений не строка — правило не совпадает. Справа можно указать путь:
`file.path starts with user.homeDir`.

**Специальные операторы**

| Оператор DSL | Синонимы | Пример   | Описание                                                                              | Типы                 |
|--------------|----------|----------|---------------------------------------------------------------------------------------|----------------------|
| **always**   | —        | `always` | Условие всегда истинно. Используется для глобального разрешения или упрощения логики. | специальный оператор |
| **never**    | —        | `never`  | Условие всегда ложно. Используется для глобального запрета или отключения правила.    | специальный оператор |

**always**

Оператор, который всегда возвращает `true`.  
Используется для:

- глобального разрешения (`permit permission.* if all: always`)
- тестирования
- отключения сложных условий
- создания fallback‑правил

**never**

Оператор, который всегда возвращает `false`.  
Используется для:

- глобального запрета (`deny permission.* if all: never`)
- временного отключения правила
- явного отрицания без условий

### Значение

Поддерживаются:

- строки в одинарных или двойных кавычках: `'text'`, `"text"`
- числа, в том числе дробные и отрицательные: `42`, `-1`, `0.5`
- булевы `true` / `false`
- `null`
- массивы литералов `[1, 2, 3]` / `['foo', false, null, 1, -2, 3.5]`
- пути без кавычек: `user.id`, `env.request.ip`

Внутри массива допускаются только литералы: пути и вложенные массивы — ошибка разбора.

Примеры значений:

```dsl
# возраст пользователя больше 18
user.age greater than 18

# массив ролей содержит роль 'admin'
user.roles contains 'admin'

# тэг заказа либо 'vip', либо 'priority'
order.tag in ['vip', 'priority']

# токен пользователя не null
user.token is not null

# проверка, что у пользователя есть отчество (даже если оно null)
user.middleName is defined
```

### Аннотации правил

Аннотации указываются **непосредственно перед определением правила** (каждая на отдельной строке). Формат:
`@имя_аннотации значение`.

#### Поддерживаемые аннотации

| Аннотация      | Тип значения       | Обязательная | Значение по умолчанию      | Описание                                        |
|----------------|--------------------|--------------|----------------------------|-------------------------------------------------|
| `@id`          | строка             | нет          | автоматически генерируется | Уникальный идентификатор правила.               |
| `@name`        | строка             | нет          | формируется из правила     | Человекочитаемое название правила.              |
| `@description` | строка             | нет          | –                          | Подробное описание того, что проверяет правило. |
| `@disabled`    | `true` или `false` | нет          | `false`                    | Если `true`, правило игнорируется при проверке. |

## Алиасы

Алиасы — это заранее определённые правила, которым присваивается уникальный ключ.
Алиас можно использовать в политике по имени, без необходимости повторять само правило.

Алиас всегда представляет ровно одно правило.

**Пример:**
```
@name "User is administrator"
alias isAdmin:
  user.roles contains 'admin'

permit permission.order.update if any:
  user.roles contains 'writer'
  isAdmin
```

Правила алиасов:

- алиас должен быть определён **до** его использования в политике, иначе будет ошибка `Unknown alias`;
- имя алиаса уникально и не содержит точек;
- в теле алиаса ровно одно правило;
- перед использованием алиаса в политике можно указать аннотации правила (`@name`, `@id`, `@description`,
  `@disabled`) — они применятся только к этому месту использования.

### Аннотации алиасов

Аннотации указываются **непосредственно перед определением алиаса** (каждая на отдельной строке). Формат:
`@имя_аннотации значение`.

#### Поддерживаемые аннотации

| Аннотация      | Тип значения       | Обязательная | Значение по умолчанию       | Описание                                              |
|----------------|--------------------|--------------|-----------------------------|-------------------------------------------------------|
| `@name`        | строка             | нет          | формируется из ключа алиаса | Человекочитаемое название алиаса/правила.             |
| `@description` | строка             | нет          | –                           | Подробное описание того, что проверяет алиас/правило. |
| `@disabled`    | `true` или `false` | нет          | `false`                     | Если `true`, алиас игнорируется при проверке.         |

## Environments (Окружение)

В правой части правила можно ссылаться не только на литералы или поля ресурса, но и на **переменные окружения** — данные, которые передаются в момент проверки политики (например, IP-адрес запроса, текущее время, параметры сессии).

### Синтаксис

Используйте префикс `env.` перед dot‑notation путём:

```
<subject> <operator> env.<path>
```

### Примеры

```
# Разрешить доступ только с локального хоста
permit permission.admin if all:
  env.request.ip equals '127.0.0.1'

# Запретить операции после рабочего времени (часы передаются числом)
deny permission.order.create if all:
  env.hour greater than or equal 18

# Проверка роли из контекста аутентификации
permit permission.report.view if all:
  env.auth.roles contains 'analyst'
```

### Где используются environment‑переменные?

 - В `resource` (правая часть правила)
 - В `subject`, если указано `env`.
 - в левой части (например, `env.user.id equals resource.owner_id`)

### Примечания

 - Environment передаётся отдельно от основного ресурса третьим аргументом `resolve()` или `enforce()`.
 - Пути с префиксом `env.` ищутся **только** в environment. Поле `env` внутри ресурса не используется, поэтому
   подменить окружение через данные ресурса нельзя.
 - Если путь в `env.` не существует или окружение не передано, значение считается `undefined`.
 - Не путайте `env.` с полями самого ресурса — они относятся к разным контекстам.

## Проверки при разборе DSL

Парсер выбрасывает `AbilityDSLSyntaxError` (экспортируется из пакета) с номером строки, колонкой и фрагментом DSL,
если:

- **Аннотации**
    - аннотация неизвестна (например, опечатка `@diasbled` — парсер подскажет `@disabled`);
    - одна и та же аннотация указана дважды для одного элемента;
    - у `@id`, `@name`, `@description`, `@priority`, `@tags` нет значения;
    - `@priority` не целое число, `@disabled` не `true`/`false`;
    - в `@tags` есть пустой тег или тег с пробелами/скобками;
    - аннотация не допускается для элемента (например, `@priority` у группы);
    - аннотация ни к чему не относится (например, стоит в конце файла).
- **Идентификаторы**: `@id` повторяется у двух политик, двух групп или двух правил.
- **Структура**
    - политика без правил;
    - политика, в которой есть только блок `except`;
    - пустая группа `all of:` / `any of:` или пустой блок `except`.
- **Алиасы**: неизвестный алиас (или использование до определения), повторное определение, алиас без правила или с
  несколькими правилами, точка в имени алиаса.
- **Значения**
    - идентификатор без кавычек и без точки справа (`user.role equals admin`);
    - путь или вложенный массив внутри массива;
    - значение не подходит оператору: сравнение (`>`, `<`, длина) — не число; `in` / `not in` — не массив;
      `starts with` / `ends with` — не строка; `equals` — массив; `contains all` / `contains any` — пустой массив.
- **Лексика**: неизвестный символ, незакрытая строка, некорректное число (`10abc`, `10.`).

## Частые вопросы

### Почему `except` не проверяется, если основная группа ложна?

Потому что except — это исключение из уже выполненной политики, а не альтернативная ветка.
Если политика не собирается применяться (основная группа ложна), то и отменять нечего.

### Почему нет операторов для дат?

Сравнение дат требует разбора форматов, часовых поясов и календарной логики — это противоречит идее лёгкого движка
без зависимостей. Передавайте даты и время числами (timestamp, час, день недели) через ресурс или environment и
сравнивайте их обычными числовыми операторами: `env.hour less than 18`, `order.createdAt greater than env.minTimestamp`.

### Что происходит с отключёнными правилами и группами?

Отключённые (`@disabled`) правила и группы не участвуют в проверке. Если в группе не осталось активных правил, группа
пропускается. Если в политике не осталось ни одной активной группы, политика **не совпадает** — она не может выдать
`permit` или `deny` без условий.
